# BioFuel-Hub
***Проект:*** BioFuel-Hub 
## Название и концепция (README.md)
  ### Название приложения
   ***BioFuel-Hub***

***Краткое описание
BioFuel-Hub*** — это специализированная B2B-платформа для индустрии альтернативного топлива, с фокусом на производство топливных брикетов (RUF, Pini&Kay, Nestro). Сервис позволяет производителям управлять остатками сырья (опилки, лузга, торф), рассчитывать энергетическую эффективность брикетов, отслеживать цепочку поставок (ChainFraction) и находить оптовых покупателей. Это экосистема для оптимизации производства и логистики в сфере биоэнергетики.

### Целевая аудитория
- Производители брикетов и пеллет (малый и средний бизнес).

- Поставщики сырья (деревообрабатывающие комбинаты, агропредприятия).

- Оптовые покупатели (ТЭЦ, котельные, экспортные компании).

- Технологи (инженеры, ищущие рецептуры смесей).


### Ключевой функционал


+ Калькулятор себестоимости: расчет стоимости брикета в зависимости от влажности, плотности и типа сырья.


+ ChainFraction (Цепочка поставок): визуализация происхождения партии сырья (от поставщика до готовой упаковки).


+ Маркетплейс: биржа заявок на покупку/продажу брикетов и сырья.


+ Лаборатория качества: база данных результатов тестирования (зольность, теплотворная способность) с возможностью сравнения.

## 2. Структура приложения (8+ разделов)

## 3. Технологический стек и обоснование
 ####  Frontend
   ***Фреймворк:*** React (Vite)

***Обоснование:*** React имеет самую большую экосистему для сложных интерфейсов. Нам потребуется сложная логика работы с формами (калькулятор) и графиками (визуализация ChainFraction). Vite обеспечит быструю горячую перезагрузку (HMR), что критично при разработке компонентов с большим количеством вычислений.

***Роутер:*** React Router v6

***Обоснование:*** Стандарт де-факто для React. Позволит легко реализовать вложенные маршруты для /auth/* и защищенные приватные маршруты (Private Routes).

***State-менеджмент:*** TanStack Query (React Query) + Zustand

***Обоснование:*** TanStack Query идеально подходит для управления асинхронными данными (API запросы, кэширование списка продуктов). Zustand будет использован для глобального состояния UI (тема, выбранная роль пользователя, корзина сравнения товаров), так как он легковеснее Redux и не требует boilerplate-кода.

***UI Библиотека:*** Tailwind CSS + Shadcn/ui

***Обоснование:*** Tailwind позволяет быстро кастомизировать дизайн под индустриальную тематику (серые, зеленые тона). Shadcn/ui даст готовые, доступные компоненты (модальные окна, таблицы, графики), которые легко адаптировать под отображение технических характеристик топлива.

***Backend
Язык и фреймворк:*** Python (FastAPI)

***Обоснование:*** В проекте присутствует сложная бизнес-логика: калькулятор теплотворной способности (формулы на основе влажности и плотности), алгоритмы построения графов для ChainFraction. Python — лучший выбор для реализации таких математических и аналитических функций. FastAPI предоставляет высокую производительность (асинхронность), автоматическую генерацию OpenAPI (Swagger) документации для API и встроенную валидацию данных через Pydantic, что критически важно для безопасности транзакций на маркетплейсе.

***База данных:*** PostgreSQL

***Обоснование:*** Реляционная модель идеально подходит для учета остатков товара, пользователей и заказов. PostgreSQL поддерживает JSONB поля (для гибких характеристик брикетов), а также расширение PostGIS, если в будущем потребуется гео-аналитика (поиск ближайших поставщиков сырья).

Инфраструктура (DevOps)
***Хостинг Frontend:*** Vercel или Netlify.

***Обоснование:*** Простота деплоя из Git (GitHub), автоматическое обновление, встроенные CDN для быстрой загрузки статики.

***Хостинг Backend & БД:*** Yandex Cloud / AWS EC2 + RDS (или Render.com для старта).

***Обоснование:*** Для бэкенда нужна поддержка асинхронных задач (например, расчет рентабельности партии в фоне). Подойдут контейнеры (Docker) с оркестрацией. Render.com предлагает простой деплой монолита с автодеплоем по Git, что упрощает запуск MVP.

## 4. Интерактивные прототипы интерфейса (Концептуальное описание)
##### 1. Калькулятор брикета (/calculator)
   * ***Интерактивность:*** Слайдеры для выбора "% влажности" (от 8% до 20%) и "Фракция сырья". Чекбоксы "Добавить связующее (крахмал)".

   * ***Динамика:*** При изменении параметров, блок справа пересчитывает результат в реальном времени (без перезагрузки):

   * ***Теплотворная способность:*** 4.2 кВт*ч/кг -> 4.7 кВт*ч/кг.

   * ***Себестоимость тонны:*** 8 500 руб -> 9 200 руб.

   * ***Визуализация:*** График "Калорийность vs Зольность".

##### 2. ChainFraction (Граф поставок)
   ***Интерфейс:*** Визуализация на основе библиотеки React Flow.

***Сценарий:*** Пользователь заходит в карточку партии брикетов "Эко-Био 001". Под блоком характеристик находится интерактивная схема:

* ***Узел 1 (Сырье):*** "ООО ЛесПром" -> 120 тн опилок (влажность 45%).

* ***Узел 2 (Переработка):*** "Сушильный комплекс №3" -> затраты газа 500 м3.

* ***Узел 3 (Прессование):*** "Линия RUF-100" -> давление 220 бар.

* ***Узел 4 (Результат):*** Готовые брикеты.

***Взаимодействие:*** Клик на узел открывает модальное окно с документами (договор поставки, акт о сушке). Это обеспечивает прозрачность происхождения товара (ключевая ценность для экспортеров).

##### 3. Дашборд производителя (Личный кабинет)
   ***Интерфейс:*** Таблица с остатками.

***Фича:*** Кнопка "Выставить на биржу" рядом с каждой партией. При нажатии выезжает сайдбар (Drawer) с предзаполненными полями: качество, цена за тонну, доступный объем. Пользователь подтверждает — объявление моментально появляется в /marketplace без необходимости заполнять длинные формы заново.

## 5. Схема данных и API
 ```  ***Схема данных*** (Основные сущности PostgreSQL)
   sql
   -- Пользователи (расширенная модель)
   Users (
   id UUID PK,
   email VARCHAR UNIQUE,
   role ENUM('admin', 'producer', 'buyer', 'supplier'),
   company_name VARCHAR,
   verification_status ENUM('pending', 'verified', 'rejected'),
   created_at TIMESTAMP
   )

-- ***Сырье*** (для цепочки)

RawMaterials (

id UUID PK,
user_id FK (Users), -- кто продает/использует
type VARCHAR, -- 'wood', 'husk', 'peat'
moisture_percent DECIMAL,
quantity_kg DECIMAL,
location_coords POINT
)

-- Партии готовой продукции (Брикеты)
Products (
id UUID PK,
producer_id FK (Users),
raw_material_id FK (RawMaterials), -- привязка к происхождению
shape ENUM('ruf', 'pini_kay', 'nestro'),
ash_content DECIMAL,
calorific_value DECIMAL, -- расчетное поле
price_per_ton DECIMAL,
stock_kg DECIMAL,
created_at TIMESTAMP
)

-- Цепочка поставок (ChainFraction)
SupplyChainNodes (
id UUID PK,
product_id FK (Products),
node_order INT, -- порядок в цепочке
node_type VARCHAR, -- 'harvesting', 'drying', 'pressing', 'packaging'
metadata JSONB -- параметры процесса (температура, давление)
)

-- Заказы на маркетплейсе
Orders (
id UUID PK,
buyer_id FK (Users),
product_id FK (Products),
quantity_kg DECIMAL,
status ENUM('pending', 'paid', 'shipped', 'completed'),
total_amount DECIMAL
) 
```
